## Decisions and limits

- Document/email reservations are conservative **attempt accounting** at the existing admission/delivery boundary. A later storage, transport or database failure can consume allowance; there is no refund/outbox redesign. Deletion does not refund it. Existing usage whose pre-control organisation/counters were already deleted cannot be reconstructed.
- Paid checkout retains one pending conversion organisation and shares the existing trial budget/window. Trial-organisation restriction applies to new external organisations; this PR does not grant internal status based on email domains or client input.
- Input defaults: 2 MiB general JSON, 12 MiB tRPC JSON, 70 MiB REST/tRPC multipart, 51 MiB ordinary upload and 129 MiB lease multipart. File allowances remain 50/128 MiB. Four active body handlers, two uploads, 64 queued descriptors and 30-second admission/input deadlines. Upload attempts: 60/user/hour. External trial API: 100/owner/minute; the dangerous test bypass cannot disable trial policy.
- Media: two workers, 256 MiB retained input across active/queued tasks, 128 MiB PDF input/output, 1,000 PDF pages; images 8 MiB and 16 million input pixels; worker deadline 30 seconds, Sharp deadline 10 seconds. AI rendering allows 20 pages/request and 4 million pixels/4,096 pixels per canvas dimension, downscaling oversized pages proportionally; aggregate rendered-image bytes are bounded.
- AI: 20 requests/user/day, provider calls 100/user/day, 500/org/day and 1,000/instance/day; 4 active instance leases, 2/org and 1/user. Whole request 60 seconds, provider fetch/body 20 seconds, lease expiry 120 seconds. Draft response 256 KiB; Vertex response 1 MiB; detection output 4,096 tokens, no retries. These technical ceilings apply to all accounts and are constants. Only trial product allowances are admin editable in this PR.
- Domain challenges last 24 hours, pending caps 5/org and 20/owner, create attempts 60/owner/hour and verification attempts 120/org/hour. Existing exclusive domain cap 100/org is retained at promotion. Canonicalization folds case/trailing dot; DNS proof does not authorize takeover from a known owner. Legacy SES delete/re-registration operations remain for existing domains; pending deletion avoids SES entirely.
- Worker heap limits do **not** isolate native/external memory, CPU or storage across the VPS. Production container capacity/CPU/memory limits remain an operational follow-up for the authorized shipping/operations session, with capacity reserved for PostgreSQL and sibling apps. No live settings, container, database, credentials or provider were accessed here. Do not mark deployment/resource-isolation complete from this code PR.
