# Files BizRethink owns that live in upstream directories.
#
# WHY THIS FILE EXISTS
#
# The fork rule is "upstream files are modified only through overlays/*.patch",
# and the governance guard enforced it by PATH: anything under apps/ or
# packages/ that is not packages/bizrethink/ was treated as upstream.
#
# That test is wrong for one unavoidable case. Remix discovers routes by
# filesystem convention, so a route we write MUST live in
# apps/remix/app/routes/ — it physically cannot go in a package. The same
# applies to the components a route imports. Those files are not upstream
# files; they have never existed upstream and never will. But the guard could
# not tell the difference, so every lease-builder PR failed it and was merged
# over the failure. A guard that is always red is a guard nobody reads, which
# is the precise failure mode the discipline system exists to prevent (see
# docs/STATE.md on PR #1 merging red, and the E2E gate going dark twice).
#
# So ownership is now declared rather than inferred. Adding a line here is a
# deliberate, reviewable act — which is the discipline the path rule was
# reaching for in the first place.
#
# RULES
#
#   - One glob per line. `#` starts a comment. Matched with `grep -E` after
#     glob-to-regex conversion, anchored at both ends.
#   - A path listed here MUST NOT exist in documenso/main. If upstream ever
#     adds a file at one of these paths, the sync will conflict — which is the
#     correct, loud outcome, and the signal to rename ours.
#   - This is NOT an escape hatch for editing upstream files. Editing an
#     upstream file still requires an overlay. This only says "this file is
#     ours, it was never theirs".

# The reviewer's side of the review loop. Lives in `_recipient+` because that
# group exists for exactly this case — upstream's own comment: "a layout to
# handle scenarios where the user is a recipient of a given resource where we
# do not care whether they are authenticated or not". It also already carries

apps/remix/app/routes/_recipient+/lease-review.$token.tsx
apps/remix/app/routes/_recipient+/lease-review.$token.document.tsx

# One attached document — a declaration, an amendment, a condition report —
# served to a reviewer or signer by token. Alongside the lease PDF rather than
# inside it: upstream's EnvelopeAttachment carries a URL and not bytes, so a
# file in the signing package would have to be an EnvelopeItem the signer
# scrolls, and the condition report for one house is 418 pages.
#
# Listed individually rather than widening the two lines above to a glob, for
# the reason the admin block gives: `_recipient+` is upstream's route group and
# a wildcard there would exempt their files to cover ours.
apps/remix/app/routes/_recipient+/lease-review.$token.attachment.$documentId.tsx

# The same document, served to a SIGNER. The route above is scoped to a REVIEW
# token, and the signing view had no attachment route at all — so the receipt
# addendum's "has had the opportunity to read them" was true of a reviewer and
# false of the one person it binds.
#
# Keyed on the matter because `EnvelopeAttachment` carries one URL for every
# recipient (no per-signer token can go in it) and is created in the same call
# as the envelope (so there is no envelope id yet). Listed individually, for the
# reason the line above gives.
apps/remix/app/routes/_recipient+/lease-attachment.$matterId.$documentId.tsx

# Counsel's side of the same loop. The clause library was always meant to be
# read by an attorney — the approval form asks for a bar number — but the page
# sat behind an authenticated route with no way to send it, so the only path
# was to add the lawyer to the organisation. Read-only by design: sending a
# link should not be the same act as granting write access.
apps/remix/app/routes/_recipient+/clause-review.$token.tsx

# The MCA vertical's equivalent, and a SECOND route rather than a mode on the
# one above (ADR 0008: two surfaces, two release paths). A lease review link is
# scoped by a jurisdiction because a lease is one document a state decides; an
# MCA deal is a SET of documents, and a link there carries one AGREEMENT. The
# two tokens live in different tables for the same reason, so one route
# resolving both would have to know which — see additions.prisma.
#
# Read-only, and narrower than the lease's on purpose: it takes no findings,
# because MCA findings already have a register in lombard-contracts and a
# second one would drift from it.
apps/remix/app/routes/_recipient+/mca-clause-review.$token.tsx
