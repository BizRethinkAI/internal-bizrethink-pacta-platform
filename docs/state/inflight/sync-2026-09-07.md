### The signing overlay had to grow an argument

Upstream #3309 rewrote `getCertificateStatus` to inspect the *actual* signer
rather than stat a file, and to call `createLocalSigner({ buildChain: false })`
so a health check does not hit the network for AIA intermediates. Our overlay 011
version of `createLocalSigner` took no arguments.

It now accepts upstream's `{ buildChain }` option and still resolves cert and
passphrase from `BizrethinkInstanceSigningConfig` before falling back to env.
This is failure mode #1 in `UPSTREAM.md`, and the fix is the one that file
prescribes: extend our overlay to accept the new shape, do not revert upstream.

**A side effect worth knowing:** because cert-status now inspects the signer this
function returns, `/api/health` and `/api/certificate-status` report on the cert
we actually sign with — the DB-sourced one included. Before, they only ever
looked at env. That is an improvement, and it is also a behaviour change on a
cryptographically load-bearing surface, so it is called out here rather than
buried in the diff.

Transport selection also now defers to upstream's `NEXT_PRIVATE_SIGNING_TRANSPORT()`
for its env fallback, because #3309 gave that constant the same `|| 'local'`
default our overlay used to spell out. One less divergence.

### We did NOT follow upstream's build heap raise

Upstream #3332 sets `NODE_OPTIONS=--max-old-space-size=8192` in the installer
stage. **Overlay 003 deliberately keeps 4096.** The Coolify host that builds this
image has 8GB of RAM *total*; telling V8 it may grow the heap to 8GB leaves
nothing for the OS and re-creates the silent build OOM this repo already paid
for on a 4GB VPS. Build peaks around 4GB.

If the Docker build ever dies on heap exhaustion, raise it incrementally. Do not
jump to 8192 on an 8GB box. The reasoning is in the Dockerfile, next to the line.

Also taken from upstream in that file: `npx turbo` instead of bare `turbo`, and
`prisma generate --generator client` in the runner stage (upstream narrowed it to
the client generator and added a cache clean; the kysely/json/zod generators only
produce build-time types, so the runner does not need them).

### The translation catalogues needed an entry-aware merge

A plain text merge of `web.po` splits entries down the middle: it left a `msgid`
with no following `msgstr`, which is a broken catalogue. A blind union merge is
worse — for the entries where upstream only changed the *value* it produces two
`msgstr` lines for one `msgid`.

These are generated, append-mostly, msgid-keyed files, so they were merged at
**entry granularity**: each entry folded onto one line with a sentinel, run
through `git merge-file`, then resolved per entry against the merge base rather
than per hunk. Per-hunk was tried first and was wrong — git groups adjacent
entries into one hunk, so "take ours" there silently discards upstream-only
changes to the neighbours.

Result: 5 disjoint insertions per locale kept from both sides, 59 (en) + 54 (pl)
entries taken from upstream where only upstream changed them, and exactly **five
entries genuinely changed on both sides** — all five upstream's British → US
spelling fix (#3329) on strings we have no rebrand stake in, so upstream won.
`Pacta` occurrence counts are identical before and after in every locale, and no
new duplicate `msgid` was introduced.

**`fr/web.po` is corrupt upstream and it is not ours to fix.** It contains a NUL
byte and a committed conflict artifact — `msgstr "<<<<<<< Updated upstream======="`
for msgid `"Attachment removed successfully."` — byte-identical in the merge
base, our `main`, and `upstream/main`. The NUL is why git treats that file as
binary and refused to text-merge it at all; it was merged explicitly instead.
Worth reporting upstream.

## A tool that lies: the overlay reverse-apply check

`git apply --check --reverse overlays/*.patch` looks like a drift detector and is
not one — **38 of 46 patches fail it on pre-merge `main`.** The patches are
historical records generated at different times, not re-appliable artifacts.

Only the *delta* means anything. After this merge exactly two newly fail —
`011a-instance-signing-config` and `070-ship-mca-sources` — and both are files
resolved by hand above. Both patches were regenerated against the merged tree.
