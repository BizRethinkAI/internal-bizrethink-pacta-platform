## Result

- **A-17:** the real `/ingest/*` route delegates to an owned analytics proxy. It builds a fresh URL on the same fixed EU PostHog hosts, forwards event bodies and the public project key, and allowlists only Accept/Content-Type/Content-Encoding plus static-file cache validators. Cookie, Authorization, CSRF/API-key headers, Referer and forwarded client addresses do not leave Pacta. Credentials are omitted and redirects rejected. Responses preserve content/cache headers, status and streams, excluding vendor Set-Cookie and decoded transport headers. Provider errors produce a generic 502.
- **A-21:** the shared Pino logger uses one owned metadata allowlist before interpolation/serialization and again at final serialized output. The latter is essential: this Pino version resets binding formatters on children. Nested children, setBindings, serializers, free-text formatting and message prefixes cannot reintroduce arbitrary payloads or bearer paths into either JSON/file or pretty transports.
- Routine diagnostics retain levels/timestamps, fixed event names and source components, route categories, server-generated request IDs, numeric IDs/counters, one-way string-ID correlations and known application/Prisma/network error codes. They omit payload/input/header objects, client addresses, user agents, raw errors/stacks, arbitrary strings and unknown keys. Signup closure retains an explicit unavailable/invalid-settings reason. Input objects and durable application/audit records are not mutated.
- Inherited server console call sites delegate to an owned scoped adapter, covering auth, recipient/template operations, server errors, jobs, providers and data-processing helpers. Local and BullMQ job dispatch no longer supply their full payloads to a logger; their task loggers bind a stable job ID. Inngest uses the same safe adapter. Optional Prisma query diagnostics keep duration only, omitting SQL and parameters. The two finding-specific tRPC routes log an access **attempt** and non-bearer ID instead of token-bearing input. Root/embed error boundaries render on the server as well as in the browser; their render-time diagnostics now accept only fixed source labels and a validated HTTP status through a browser-safe owned helper. Existing browser-only analytics effects are unchanged.
- Hono generates its own request ID and returns it in X-Request-Id; tRPC shares it. An untrusted incoming request ID cannot become a log field. The root error handler logs safely and preserves Hono HTTPException response semantics. Request metadata remains available for authorization and durable audit use.
- Sentry error/transaction exports are freshly constructed safe records; URLs/parameters, users, arbitrary tags/context, raw exceptions, breadcrumbs and span data are omitted. Error grouping uses a one-way digest of code locations. Safe event/trace IDs and transaction timing remain. Sentry log exports and local-variable capture are disabled. The existing server Rollup entry re-exports the owned sanitizer so the early copied instrumentation imports its generated file without starting the app/database.

## Decisions and limits

- A conservative allowlist replaces free-form diagnostic content. New useful fields/events must be explicitly registered; raw stack/message/body retention is intentionally reduced. Source component, safe reason/error codes, correlation and Sentry location digests preserve basic diagnosis/grouping, but they do not replace raw stack traces for every debugging task.
- Analytics event bodies, project keys and existing product analytics consent/data policy are preserved. This fix addresses ambient application credentials in the proxy and routine server diagnostics; it is not a broader redesign of analytics payload collection or browser-side telemetry.
- No global monkey-patch of console, process streams or third-party runtimes is installed. The source hooks cover the application's server diagnostic sinks; infrastructure access logs, fatal runtime dumps and third-party transport storage require their own operational controls.
- Historical PostHog/application-log/Sentry exposure, retention/access review and any token/session revocation remain an authorized operations follow-up. This author did not query historical/production logs, access credentials, change retention, revoke sessions or trigger any deployment. Do not mark historical disclosure or deployment resolved by merging this PR.
- Independent adversarial upstream/auth/instrumentation review remains pending. Author CI results and the final SHA are recorded on the task/PR without a status-only code push.
