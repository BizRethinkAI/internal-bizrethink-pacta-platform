# feat/mca-publication-record — the record, and the endpoint that ends the copy

**Stacked on `feat/mca-field-triage` (#293) → #292 → #290 → #289.**

## What this is

ADR 0023 §2, extended by ADR 0024: the record of what was published lives with
the producer. This adds the table, the service that writes and reads it, and the
team-scoped endpoint a caller reads it from.

## The failure it removes

`lombard-platform` vendors a **copy** of every published template into
`src/templates/*.published.json`, and its own widget-totality spec compares its
builders against `TEMPLATES[kind].acroformFields` — which reads that copy. Both
sides of the comparison come from one snapshot, so **nothing there can notice
the snapshot going stale against what is actually published.** Republish a
template without refreshing the copy and CI stays green while production drifts.

That is the cause. `lombard-platform` #262 fixes a runtime guard that had never
fired and now warns on an unknown widget name — a useful backstop, and still a
report after the fact. Serving the record from the producer means there is no
copy left to go stale.

It matters more from here, not less: ADR 0024 makes republication routine.

## Shape

- `BizrethinkMcaPublication` — **append-only**, like
  `BizrethinkMcaTemplateRevision`. A row is the record of what a merchant was
  actually sent, so re-publishing writes a new row; there is no update and no
  delete, and an earlier publication stays readable after it is replaced.
  "Current" is the newest per instrument.
- It keeps the **interface**, not only the identifier: the widget names as
  published and the signing roles with their recipient ids. A caller that got
  back only a `templateId` would still need its own copy of the names, which is
  the thing being removed.
- `GET /api/bizrethink/mca-templates` returns `templateId`, `envelopeId`,
  `acroformFields` and `recipients` **keyed by role** — the shape
  `*.published.json` already has — so adopting it is a change of source rather
  than a rewrite of `sendDocument`.

## It says what each template is for

`builtForStates` and `venueRule` travel with the id and the widget names.

**Pacta labels the goods; the entity runs the business.** Which template suits a
given merchant is the entity's decision, made with the entity's own deal data —
none of which reaches this vertical, and none of which this endpoint refuses
anything on the basis of. But an entity holding two templates cannot choose
between them unless each says what it was built for.

Added after the deal-time venue guard was examined for removal: that check
belonged to the business, not to the goods, and the honest replacement is not a
refusal anywhere in Pacta but an accurate label the caller reads.

## Authorisation is the token, not a membership

`ApiToken` has a required `teamId` and a **nullable** `userId`, so a team token
need not belong to a person and the membership check the interactive services
run cannot apply. The token is the grant, bound to its own team; the feature
grant is checked on that team's organisation.

Refusals are deliberately uniform — a caller learns the token did not work,
never whether it existed, expired or belongs to a disabled account. A team
without the builder gets 404 rather than 403, because "forbidden" would confirm
that templates exist.

`no-store`, because a stale answer here is the exact problem the endpoint exists
to solve.

## Migration

`20260917010000_add_mca_publication_record` — one new table, no change to any
existing one, no backfill. Rollback is dropping it; nothing else reads it.

**`prisma format` was reverted deliberately.** It realigned whitespace across 103
lines of unrelated models. `schema.prisma` is generated by
`merge-into-schema.mjs`, and the governance workflow knows it as such, so the
checked-in file is the merge script's output and nothing else. Re-running the
merge alone gives a clean 54-line diff.

## Not in this change

Nothing writes a publication yet — there is no publication service, because
there is no merchant-ready render. `recordMcaPublication` is the seam it will
call, written first for the same reason the gate was (ADR 0020 §3.2). The
endpoint returns an empty list until then, which is correct and not a failure.

`lombard-platform` is untouched. Moving it off the vendored copy is a change in
a repository this session does not own, and it must not happen before the
builder can actually publish.

## Base, and a note about stacks

Retargeted to `main` once #293 merged. It matters, and it cost two red runs to
learn why.

Consolidation folds every in-flight note into `STATE.md` and deletes it, so
`main` carries none. A stacked branch therefore sits between two truths: its
base branch still has its ancestors' notes, and `main` does not. Merge `main`
into a branch whose base is a *merged* branch and the state-notes guard sees
four foreign notes being **deleted**; retarget to `main` before the parent lands
and it sees them being **added**. Both times the guard is right and the
sequencing is wrong.

The rule that falls out: **retarget only after the parent merges, and merge
`main` only once you have.** Against its own live base, this branch adds exactly
one note — its own.
